# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository overview

`prototipos` holds independent, experimental prototypes for the CIT/CEAEC group (a Conscienciologia community project exploring AI-assisted workflows). Each top-level folder is a self-contained prototype — nothing here is a monorepo package graph, so don't assume shared tooling across folders.

- **`curadoria/`** — plain Markdown only, no build step. `PROPOSTA.md` and `PROTOCOLO.md` define a collaborative, AI-assisted content-curation protocol; `templates/` holds the fiche (`ficha.md`) and WhatsApp-announcement (`whatsapp.md`) templates the protocol references. Treat this as the source of truth for anything about the curation protocol — other content (in `capacitacao/`) should **link to specific sections here rather than duplicate them**, to avoid two "official" copies drifting apart.
- **`capacitacao/`** — an Astro + Starlight static site, deployed to GitHub Pages, holding navigable courses built from real (not placeholder) content.

## Commands (`capacitacao/`)

```sh
cd capacitacao
npm install
npm run dev       # http://localhost:4321/prototipos/  (also shows draft: true pages, with a banner)
npm run build      # -> ./dist ; excludes draft: true pages
npm run preview    # serve the production build locally
```

`capacitacao/CLAUDE.md` (symlinked to `AGENTS.md`) has dev-server-specific guidance (run it with `astro dev --background`, manage with `astro dev stop/status/logs`) — check it before starting a dev server.

Node **>=22.12** is required (`engines` in `package.json`, and Astro 7.x itself refuses older Node). The deploy workflow pins `node-version: 22`; do not lower it — an earlier attempt at `20` failed CI outright.

## Deploying

`.github/workflows/deploy-capacitacao.yml` builds and deploys to GitHub Pages on every push to `main` that touches `capacitacao/**` or the workflow file itself (GitHub Pages source is already set to "GitHub Actions" in repo settings — nothing to configure). A deploy typically takes 1–5 minutes and sometimes queues behind other runs; poll with `gh run list --repo conscienciologia/prototipos` / `gh run view <id> --json status,conclusion` rather than assuming success right after `git push`. Verify the live URL (`curl`/`gh`) before considering a change actually published — a build can succeed while the page it built is still wrong (see base-path gotcha below).

This is a shared, actively-edited repo (the same person pushes from multiple sessions/devices, and `curadoria/` gets updated independently of `capacitacao/`). Always `git fetch origin` and check `git log --oneline HEAD..origin/main` before committing; `git pull --rebase origin main` if the remote has moved.

## Architecture notes specific to this site

### Base-path link gotcha

GitHub Pages for this repo serves at the **repo root** — `https://conscienciologia.github.io/prototipos/` — not a per-folder subpath, so `astro.config.mjs` has `site: 'https://conscienciologia.github.io'` + `base: '/prototipos'`. Getting this base right isn't enough on its own: **Starlight only auto-prefixes `base` for some link types, not others**, and mixing them up ships a page with broken CSS/nav/images without erroring at build time:

- **Base-aware (safe to write as an absolute `/path/`):** sidebar entries (manual `link:` and `autogenerate`), pagination (prev/next), `editLink`, images imported from `src/assets/` and referenced with a relative Markdown path (Astro's asset pipeline rewrites these correctly).
- **NOT base-aware (must be relative, e.g. `../../cursos/x/`, or root-relative *without* the leading slash for `hero`/`LinkCard`):** plain Markdown body links (`[text](/foo/)`), `hero.actions[].link` in a page's frontmatter, and `LinkCard`'s `href` prop.

When adding any link outside the sidebar, write it relative to the current file's position and verify with a production build + `curl`, not just `npm run dev` (dev mode tolerates path mistakes that production won't).

### Locale

Single-locale Portuguese site via `locales: { root: { label: 'Português', lang: 'pt-BR' } }` in the Starlight config. **`defaultLocale` alone does nothing** — it only selects a key out of an already-declared `locales` map, so setting `defaultLocale: 'pt-BR'` without a matching `locales` entry silently keeps the English UI strings (this was tried and failed before the current config).

### Content conventions

- Lessons are plain `.md` (not `.mdx`) using Starlight's colon-fence asides — `:::tip[title]`, `:::note`, `:::caution`, `:::danger` — no component import needed. `src/content/docs/index.mdx` is the one exception, since the homepage uses `<Card>`, `<CardGrid>`, `<LinkCard>`, `<Aside>` from `@astrojs/starlight/components`.
- Files are named `NN-slug.md` (zero-padded) per course folder; this prefix controls both the autogenerated sidebar order and prev/next pagination. The frontmatter `title` repeats the same number ("N. Title") — keep both in sync manually when reordering or inserting a lesson.
- `src/content.config.ts` extends Starlight's `docsSchema` with two custom optional fields: `duration_minutes` (number) and `objectives` (string array). Don't add more schema fields speculatively — the project has deliberately kept frontmatter minimal.
- `draft: true` in a page's frontmatter excludes it from `npm run build` (and from sidebar `autogenerate`) while keeping it visible under `npm run dev` with a "rascunho" banner. A sidebar group whose `autogenerate` directory is *entirely* drafts still renders as an empty, clickable dead-end in production — don't wire a sidebar entry to an all-draft directory.
- Course folders under `src/content/docs/cursos/`: `cosmoetica-ia/` (public-facing training), `curadoria-colaborativa/` (internal, teaches the `curadoria/` protocol by linking to it), `editar-com-github/` (practice area for contributing to this site itself via GitHub + an AI assistant — graduated exercises from "edit one sentence" to "edit `curadoria/PROTOCOLO.md` consistently across its citations" to "create and publish a whole new course").
